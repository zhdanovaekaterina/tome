# Contributing Guide

Обязательно соблюдение правил организации кода (`docs/coding-rules.md`)

## Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone git@github.com:zhdanovaekaterina/tome.git
cd tome

# 2. Установить виртуальное окружение и зависимости
python3 -m venv .venv
pip install .

# 3. Настроить git hooks
chmod +x -R .githooks
git config core.hooksPath .githooks
```

## Тесты

```bash
pytest -v               # все тесты
pytest --cov=src        # покрытие
```

## Процесс работы с Git

### Ветки

```
main        — стабильная версия
feature/*   — новая функциональность
fix/*       — исправления
```

### Коммиты (Conventional Commits)

Формат: `<type>(<scope>): <описание>`

# Версионирование: быстрая памятка

## Формат
MAJOR.MINOR.PATCH

## Когда что

| Изменение | Версия |
|---|---|
| Несовместимое API / БД / модель | **MAJOR** |
| Новая функциональность | **MINOR** |
| Багфикс, рефакторинг, правка справочника | **PATCH** |
| Обязательное поле + миграция | **MINOR** |
| Обязательное поле без миграции | **MAJOR** |
| Enum с сериализацией + переименование | **MAJOR** |
| Enum без сериализации + переименование | **MINOR** |
| Удаление endpoint | **MAJOR** (сначала deprecation) |
| Формат ошибок изменён | **MAJOR** |

## Версии

| Версия | Когда |
|---|---|
| `0.x.y` | До MVP. Ломать свободно |
| `1.0.0` | MVP: API стабилен, README готов |
| `1.x.y` | Расширения без ломания |
| `2.0.0` | Ломающие изменения |

## Где хранить

- `pyproject.toml` — источник истины
- `src/tome/__init__.py` — `__version__`
- `GET /version` — API
- Git tag `v*.*.*` — на релизах
- `CHANGELOG.md` — обновлять перед релизом

## Правила

1. Не менять версию в каждом коммите. Только вехи.
2. Не начинать с 1.0.0. До MVP — `0.x.y`.
3. CHANGELOG обновлять **перед** релизом.
4. Tag на каждый релиз.
5. Не путать MAJOR (ломающее) и MINOR (добавление).
6. Релизить каждые 2-4 недели в активной фазе.
